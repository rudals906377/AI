# 뷰티 스타일 AI 분석

헤어스타일 · 네일아트 · 메이크업 · 타투 사진을 올리면 **브라우저 안에서** AI가 스타일을 한국어로 설명합니다.
서버가 없고 사진이 외부로 전송되지 않습니다. 모델은 Transformers.js 로 브라우저에서 직접 실행됩니다.

**데모**: https://huggingface.co/spaces/kyoungminOh/beauty-style-ai

## 사용 방법

1. **내 사진 올리기** 버튼을 누르거나, 사진을 끌어다 놓거나, 복사한 사진을 붙여넣기(Ctrl+V) 합니다. 휴대폰에서는 **사진 찍기** 버튼으로 바로 찍을 수 있습니다.
2. 올리면 바로 분석합니다. 예시 사진은 헤어 · 네일 · 메이크업 · 타투 탭에서 골라 누르면 됩니다.
3. 모델 · 카테고리 · 고급 모드(AI 자유 서술)는 **분석 설정**을 펼쳐 바꿉니다. 카테고리를 바꾸면 바로 다시 분석합니다.
4. 결과의 **시술 요청서**는 복사하거나 **이미지로 저장**해 매장에 보여 줄 수 있습니다. 휴대폰에서는 공유 창(카카오톡 · 메시지)이 바로 열립니다.
5. 전문가 검수는 화면 아래 **전문가 검수 도구**(`review.html`)에서 합니다.

| 트렌드 키워드 | `오피스네일` `쇠맛 네일` `자석네일` 처럼 인스타그램 · 네이버에서 실제로 검색하는 말 |
| 설명 문장 | "적당한 미디엄 길이에 스퀘어 쉐입, 누드·베이지 컬러를 올린 프렌치 네일로 보여요. 마감은 은은하게 빛나는 펄 마감으로 보여요. SNS에서는 '오피스 네일'로 많이 찾는 스타일이에요." |
| 사진 속 색 | 머리카락 · 입술 · 눈두덩 · 손톱 부분만 찾아 뽑은 색 (HEX, 가까운 색 이름, 헤어는 약 몇 레벨인지). 조명에 따라 달라질 수 있다고 함께 안내 |
| 시술 요청서 | 디자이너 · 네일리스트 · 아티스트 · 타투이스트에게 보여 줄 요약. 확신 있는 항목은 표로, 확실하지 않은 항목은 "상담 때 정할 것"으로, 탈색 · 연장 · 아트 추가금 같은 참고 안내를 붙임. 복사 · 이미지 저장 |
| 이런 분께 잘 어울려요 | 스타일 특징에 일반적인 스타일링 기준을 적용한 추천. 헤어는 얼굴형 · 퍼스널 컬러 · 어깨선 · 체형 · 모질 · 추구미 · 어울리는 자리 · 관리, 메이크업은 얼굴형 · 퍼스널 컬러 · 눈매 · 입술 · 피부 유형 · 추구미, 네일은 손 모양 · 피부 톤 · 손톱 상태 · 생활, 타투는 피부 톤 · 피부 유형 · 부위 · 크기 · 관리. 확신 50% 미만인 속성은 근거로 쓰지 않음 (`suits.js`) |
| 비슷한 스타일 | 같은 카테고리 예시 사진 중 특징값이 가장 가까운 3장. 누르면 그 사진을 분석 |
| 내 얼굴 분석 (헤어 · 메이크업) | 셀카에서 얼굴 랜드마크 478점 + 부위 분할(얼굴 피부 · 머리카락 · 목 · 손)로 이마 · 광대 · 턱 · 턱끝 너비, 얼굴 길이, 삼정, 턱 각도, 눈 · 코 · 입술 비율을 재고 6가지 얼굴형에 가까운 정도(%)를 냄. 셀카를 찍을 때는 얼굴 · 목 가이드 선을 띄우고 "조금 더 가까이 와 주세요" · "턱을 조금만 들어 주세요" · "고개를 왼쪽으로 조금 돌려 주세요" · "앞머리가 이마를 가리고 있어요" 처럼 실시간으로 안내하다가, 자세가 맞으면 자동으로 찍음. 올린 사진에서 앞머리 · 옆머리 · 손이 얼굴선을 가리거나 고개가 돌아가면 가린 곳을 붉게 표시하고 다시 찍어 달라고 안내. 헤어 · 메이크업 모두 얼굴형을 보여 주고, 헤어는 추천 커트 · 앞머리 · 기장 · 가르마 · 피할 스타일, 메이크업은 얼굴형별 핵심과 쉐딩 · 하이라이터 · 블러셔 위치를 얼굴 위에 그려 주고 눈썹 · 아이라인 · 입술 · 비율 보정 추천. 직전에 분석한 스타일과의 궁합도 알려 줌. PC 는 웹캠, 휴대폰은 전면 카메라. 웹캠은 약 2초 동안 5장을 찍어 점검을 통과한 장들의 측정값 중앙값을 쓰고, 사진 정보(EXIF)에 초점거리가 있으면 카메라 거리를 어림해 너무 가까우면 안내 (`face.js` · `face-advice.js` · `face-ui.js`) |
| 용어 설명 | 라벨 406개마다 한 줄 정의 (예: 허쉬컷 "정수리부터 층을 많이 내 끝이 가볍게 흩어지는 커트예요.") |
| 함께 보이는 스타일 | 예) 메이크업하는 모습의 헤어 사진이면 메이크업도 함께 설명 (다른 카테고리도 25% 이상 뚜렷할 때) |
| 속성별 근거 | 그룹마다 상위 후보와 보정된 확률 막대 |
| 메이크업 부위 판단 | 아이섀도 · 아이라인 · 속눈썹 · 포인트는 눈 영역, 립 컬러는 입술 영역, 립 표현은 얼굴 영역만 잘라 임베딩해 판단 (얼굴을 못 찾으면 전체 사진). 교차 검증에서 아이섀도 50.6 → 64.4%, 립 컬러 59.4 → 80.6% (`docs/MODEL_CARD.md` 5-1) |
| 틀린 결과 고치기 | 항목마다 **수정**을 눌러 정답을 고르면, 사진 없이 특징값만 저장해 다음 학습에 쓸 수 있음 |
| 해시태그 · JSON | `#프렌치네일 #오피스네일 …`, 앱 연동용 JSON |

- **분류명은 한국식**입니다. 헤어는 허쉬컷 · 칼단발 · 애즈펌 · 빌드펌 · 애쉬베이지, 네일은 자석 · 벨벳 · 글레이즈드 · 오마카세, 메이크업은 물광 · 숙취 블러셔 · 언더라인 · 말린장미 같은 이름을 씁니다. 2024\~2026년 한국 매거진 · 살롱 · 쇼핑몰 · 커뮤니티에서 용어 약 440개를 조사해 324개로 정리했고(v2), 2026-10-07 에 머쉬룸컷 · A라인 보브 · 매직 스트레이트 · 머니피스 · 컷크리즈 · 스월 · 핸드포크 같은 라벨 82개를 더해 **406개**가 됐습니다(v3). 근거와 출처는 [docs/LABEL_RESEARCH.md](docs/LABEL_RESEARCH.md) 에 있습니다.
- **설명 문장은 정해진 틀을 반복하지 않습니다.** 자리마다 표현을 여러 개 두고 사진마다 다르게 고르며, 같은 사진은 늘 같은 문장이 나옵니다. 낯선 기법은 한 줄 설명을 붙이고(예: "빛을 받으면 띠 모양 반사광이 움직이는 자석젤"), 다른 이름이 있으면 "똑단발이라고도 불러요"처럼 알려 줍니다.
- **트렌드 키워드는 속성 조합으로 만듭니다.** 예) 브라운 염색 + 쿨톤 → "차가운 애쉬브라운", 크롬 · 실버 · 메탈릭 → "쇠맛 네일", 레이어드컷 + C컬펌 → "레이어드 C컬". v3.1 에서 매거진 · 네이버 블로그를 조사해 실제로 쓰이는 이름 **210개**(헤어 51 · 네일 73 · 메이크업 47 · 타투 39)를 더했습니다 — 웬디컷 · 버터플라이컷 · 부자 네일 · 테토녀 네일 · 물먹립 · 드뮤어 메이크업 · 이레즈미 등판 같은 이름입니다. 조건이 많은(더 구체적인) 이름부터 최대 4개를 보여 주고, 이름 · 뜻 · 조건 · 출처는 [docs/TREND_RESEARCH.md](docs/TREND_RESEARCH.md) (`trends.js`) 에 있습니다.
- **타투는 장르 중심**입니다. 레터링 · 파인라인 · 블랙앤그레이 · 이레즈미 · 치카노 · 동양화 등 24개 장르와 장르 설명, 부위 · 크기 · 도안을 알려 주고, 조합이 맞으면 '하찮은 타투' · '허리 라인 타투' 같은 트렌드 이름도 붙입니다.
- 뷰티 사진이 아니면 "뷰티 사진이 아닐 수 있어요", 사진이 너무 작으면 "세부 판단이 부정확할 수 있어요" 안내를 띄웁니다.

## 동작 구조

```
사진 ─▶ 비전 인코더로 임베딩 1회 ─┬▶ 뷰티 사진 판별 (학습 헤드)
                                  ├▶ 카테고리 판별 (학습 헤드 + 제로샷) ─▶ 1위 + 함께 보이는 2위
                                  └▶ 속성 그룹 32개 분류 (학습 헤드 + 제로샷 혼합 → 확률 보정)
                                          ▼
                    장르 · 트렌드 키워드 · 한국어 문장 · 해시태그 · JSON
      └▶ [고급 모드] 소형 VLM 이 사진을 보고 영어로 서술 → 뷰티 용어집 + 한국어 번역
```

| 모드 | 모델 | 다운로드 | 라이선스 |
|---|---|---|---|
| 기본 (기본값) | `Marqo/marqo-fashionSigLIP` | 약 94MB (q8) | Apache-2.0 |
| 정밀 | `Xenova/siglip-large-patch16-384` + 기본 모델 (두 모델 확률 평균) | 약 208MB (WebGPU q4) · 329MB (CPU q8), 기본 모델 94MB 별도 | Apache-2.0 |
| 고급 모드 | `onnx-community/LFM2.5-VL-450M-ONNX` | 약 420\~630MB | LFM Open License v1.0 |

- **라벨 임베딩 사전 계산**: 속성 라벨 324개의 문장 임베딩을 미리 계산해 `embeddings/` 에 넣었습니다. 브라우저는 비전 모델만 받습니다.
- **학습 헤드**: 라벨 문장 임베딩에서 출발해 검수한 사진으로 보정한 경량 분류기입니다 (`heads/`, 모델마다 약 1MB). 그룹마다 제로샷과 섞는 비율을 교차 검증으로 정하고, 교차 검증 정확도가 40% 미만인 헤드는 쓰지 않습니다.
- **고급 모드**: 이 소형 VLM은 한국어로 직접 쓰면 옷 · 배경 이야기로 새는 경향이 있습니다. 그래서 영어로 먼저 관찰하게 한 뒤 문장 단위로 번역하고, 영어 원문도 함께 보여 줍니다.

## 신뢰도: 단정하는 말은 거의 틀리지 않게

화면의 확률은 **보정된 확률**입니다. 단정하는 기준은 그룹마다 "이 확률 이상이면 95% 맞는" 값으로 따로 정했습니다 (v3.1, 공통 0.9 대신). 학습 때 폴드 밖 예측으로 그룹마다 온도를 맞춰, "80%"라고 표시하면 실제로도 그 정도로 맞게 했습니다. 설명 문장의 **모든 항목**이 이 확률로 말투를 정합니다. 여러 속성이 한 문장에 들어가면 가장 불확실한 속성을 따릅니다.

| 보정 확률 | 문장 | 실제 적중률 (기본 · 정밀) |
|---|---|---|
| 그룹별 단정 기준 이상 (0.75 \~ 0.98) | "\~예요" 단정 | **95.5% · 95.5%** (전체 판단의 36% · 42%), 정밀 모드 96.8% (35%) |
| 0.5 \~ 단정 기준 | "\~로 보여요 / \~에 가까워요" (2위가 가까우면 함께 언급) | 75.6% · 76.6%, 정밀 모드 82.2% |
| 0.5 미만 | 문장으로 말하지 않고 속성별 후보 막대로만 보여 줌 (장르 · 컬러만 "추정돼요") | 48.3% · 52.8% |
| 1위는 애매하지만 같은 계열의 합이 단정 기준 이상 | "보브 계열이에요" 처럼 계열로 단정 | 93.6% · 96.2% |

트렌드 키워드 칩과 해시태그도 보정 확률 0.5 이상일 때만 붙입니다. 적중률은 정답 후보 기준입니다 (예: 정답이 "오벌 또는 아몬드"일 때 둘 중 하나면 맞음).

### 100% 를 목표로 할 때 알아 둘 점

- **라벨 자체가 100% 일치하지 않습니다.** 같은 사진을 두 라벨러가 따로 판정하면 속성 라벨의 92% 가 일치했습니다. "오벌 vs 아몬드", "MLBB vs 로즈핑크" 처럼 사람마다 답이 갈리는 항목이 있어, 어떤 모델도 한 라벨러 기준 100% 는 나올 수 없습니다.
- 그래서 **단정하는 말**을 이 한계 가까이(95\~97%) 끌어올리고, 애매한 항목은 후보로 보여 주는 방식을 택했습니다.
- 전체 정확도를 더 올리는 가장 확실한 방법은 **한국 스타일 사진을 더 모으는 것**입니다 (아래 학습 곡선). 확대 크롭을 섞는 방법, 두 모델 앙상블, 한국 사진 가중치 조정도 시험했지만 효과가 작았습니다 (각각 +0.3%p, 0, +0.8%p).

### 배운 점

- **라벨의 정확도가 양보다 중요했습니다.** 검색어로 자동으로 붙인 라벨 1만 장은 효과가 없었습니다 (73.9% → 73.4%). 사진을 직접 보고 단 라벨은 280장만으로 +5.9%p 를 올렸습니다.
- **라벨 기준이 다르면 오히려 떨어집니다.** 3차 라벨(보조 에이전트)은 헤어 앞머리 · 네일 디자인 · 타투 장르에서는 도움이 됐지만, 네일 쉐입 · 립 컬러 · 염색 기법에서는 기준이 달라 정확도를 떨어뜨렸습니다. 그래서 그룹마다 검수 라벨로 효과를 재서, 도움이 되는 그룹에만 썼습니다.
- **모델마다 맞는 데이터가 다릅니다.** 4차 메이크업 라벨은 기본 모델의 메이크업을 올렸지만 (평가 71.4% → 76.2%) 정밀 모델은 떨어뜨려 (76.2% → 69.0%), 정밀 모델에는 쓰지 않았습니다.
- **두 모델 앙상블은 이득이 없었습니다.**
- **실제 사용 환경과 비슷한 사진이 가장 효과가 큽니다.** 한국 스타일 사진 98장을 더하자 한국 사진 정확도가 67.0% → 76.7% 로 올랐고, 서양 웹 사진 기준 검증도 함께 올랐습니다 (77.0% → 78.6%).

## 피드백으로 계속 좋아지기

상업 서비스에서 정확도를 올리는 가장 빠른 길은 실제 사용자 사진에서 틀린 사례를 모으는 것입니다. 이 앱은 사진을 저장하지 않고도 그렇게 할 수 있습니다.

1. 사용자가 결과 화면에서 **수정**을 눌러 틀린 항목의 정답을 고르거나, 카테고리를 고칩니다 ("뷰티 사진 아님" 포함).
2. 브라우저에는 **사진 대신 모델이 뽑은 특징값(임베딩)** 과 고친 라벨만 저장됩니다. 특징값에서 원래 사진을 복원할 수는 없습니다.
3. "피드백 내보내기"로 받은 파일을 학습에 그대로 넣습니다.

```bash
python3 tools/train-heads.py --commercial ... --feedback beauty-feedback-2026-10-01.jsonl
```

사용자가 고친 사례는 모델이 틀린 사례이므로, 학습 때 잡음 필터에서 빼지 않습니다. 서비스로 운영할 때는 이 파일을 서버로 모으는 부분만 붙이면 됩니다 (사용자 동의 필요).

### 전문가 검수 도구 (`review.html`)

현장 전문가가 사진 여러 장을 한 번에 올리고, AI 답을 항목마다 **맞음 · 틀림 · 판단 불가**로 표시합니다. 틀리면 정답을 고릅니다.

- 단축키: `1` 맞음 · `2` 틀림 · `3` 판단 불가 · `Enter` 남은 항목 모두 맞음 후 다음 · `←` `→` 이동
- 오른쪽에 그룹별 정확도와 확신 단계별("\~예요" / "\~로 보여요" / 문장에서 뺌) 정확도가 바로 나옵니다.
- **학습용 JSONL** 은 위의 `--feedback` 과 같은 형식이라 그대로 다시 학습할 수 있습니다. **항목별 CSV** · **요약 CSV** 는 엑셀에서 열리며, 요약 CSV 로 [docs/MODEL_CARD.md](docs/MODEL_CARD.md) 의 성능 표를 전문가 기준으로 바꿀 수 있습니다.
- 사진은 저장하지 않고 특징값과 판정만 브라우저에 저장합니다. 새로 고침 뒤 같은 사진을 다시 추가하면 이어서 볼 수 있습니다.

## 속성 사전을 고치거나 다시 학습하려면

```bash
npm i @huggingface/transformers
node tools/build-embeddings.mjs                      # taxonomy.js 수정 후 라벨 임베딩 재생성
node tools/embed-images.mjs list.json out Marqo/marqo-fashionSigLIP q8   # 사진 임베딩
python3 tools/train-heads.py --commercial --tax taxonomy.json --labels embeddings/marqo-fashionSigLIP.json \
    --train out.f32 --train-meta out.json --train-list train_list.json \
    --eval eval.f32 --eval-meta eval.json --eval-list eval_list.json --out heads/marqo-fashionSigLIP.json
```

`--commercial` 은 상업 이용 · 개작이 허용된 사진만 씁니다. 권리 미확인 사용자 제공 사진(`license: user-provided`)은 `--include-user-provided` 를 줄 때만 들어갑니다. `--user-weight 3` 은 사용자 제공 사진과 앱 피드백을 3배 비중으로 학습합니다 (현재 기본 모델 헤드의 설정). 학습이 끝나면 그룹별 정확도와 보정표(`CALIBRATION`)가 출력됩니다. 속성 사전을 바꾸면 해시가 달라져 기존 헤드는 자동으로 꺼지고 제로샷으로 동작합니다. 다시 학습하면 켜집니다.

## Hugging Face Space 배포

**자동 배포 (권장)**: `main` 브랜치가 바뀔 때마다 GitHub Actions 가 Space 로 올립니다 (`.github/workflows/deploy-space.yml`).

1. https://huggingface.co/settings/tokens 에서 **Write** 권한 토큰을 만듭니다.
2. GitHub 저장소 **Settings → Secrets and variables → Actions** 에서
   - **Secrets** 에 `HF_TOKEN` = 방금 만든 토큰
   - (선택) **Variables** 에 `HF_SPACE` = `내계정/스페이스이름`. 없으면 `내계정/beauty-style-ai` 로 만듭니다.
3. PR 을 `main` 에 병합하거나, **Actions → Deploy to Hugging Face Space → Run workflow** 를 누릅니다.
4. 몇 분 뒤 `https://huggingface.co/spaces/내계정/스페이스이름` 에서 열립니다. 스페이스가 없으면 Static Space 로 새로 만듭니다.

**직접 배포**: 내 PC 에서 한 번에 올릴 수도 있습니다.

```bash
pip install huggingface_hub
HF_TOKEN=<쓰기 토큰> python3 tools/deploy-space.py 내계정/beauty-style-ai
python3 tools/deploy-space.py --dry-run   # 올릴 파일 목록만 확인 (앱 실행에 필요한 37개 파일, 약 8MB)
```

배포 스크립트는 앱 실행에 필요한 파일 · 예시 사진 · 학습 데이터 출처 기록만 올립니다. 학습 스크립트와 문서는 올리지 않습니다.
